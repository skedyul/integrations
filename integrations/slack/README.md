# Slack

Serverless integration for Slack channels and direct messages.

One communication channel is created per connected workspace (`identifierValue` is the Slack team id). Channel and group messages arrive as group threads keyed on the Slack channel id. Each Slack workspace belongs to one workplace's own team, so every Slack conversation goes to **Ask Skedyul**. The channel has no `messaging` capability: Slack is not a customer channel, and Ask Skedyul replies through `askSkedyul.send` (`send_slack`). Slack threads created before this change are customer threads; they are migrated to Ask Skedyul threads after the platform change is deployed. The channel declares `capabilities.askSkedyul` (`conversations: ['direct', 'group']`, `addressing: 'installation'`, `matchMemberBy: ['email']`, `groupReplies: 'mentioned'`). The webhook passes the sender's Slack profile email as `identity` so the platform can match them to a workplace member, and `mentioned: true` when a message @mentions the app. Ask Skedyul replies to every DM; in channels it replies only when mentioned, while every message is kept for context.

Set `SLACK_CLIENT_ID`, `SLACK_CLIENT_SECRET`, and `SLACK_SIGNING_SECRET` on the app version. After provision, paste the logged Events API URL into the Slack app. Bot scopes: `chat:write`, `channels:history`, `channels:read`, `groups:history`, `groups:read`, `im:history`, `im:read`, `mpim:history`, `mpim:read`, `users:read`, `users:read.email`. Reconnect Slack after those read scopes are added to the Slack app so the bot token is replaced. Channel and group messages are external conversations. `conversations.info` and `conversations.members` supply the room name and people; a failed lookup is logged (for example `missing_scope`) and the message is still received. The next message after a successful lookup sets the thread title and adds the people Slack returned.
